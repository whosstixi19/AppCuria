\section{Requisitos de hardware para el Servidor Físico (Escenario 1)}
Para el equipo físico principal donde se alojarán el sistema operativo, el motor de base de datos y la aplicación en red local, se recomienda una estación de trabajo o computadora de escritorio con las siguientes características operativas:
\begin{itemize}
    \item \textbf{Procesador:} Intel Core i5/i7 (8va generación o superior) o AMD Ryzen 5/7, con 4 a 8 núcleos (arquitectura x64).
    \item \textbf{Virtualización por Hardware:} Obligatoria si se utiliza Docker Desktop (Intel VT-x o AMD-V habilitada en la BIOS/UEFI). Para verificarlo en Windows: presione \texttt{Ctrl + Shift + Esc} (Administrador de tareas) $\rightarrow$ pestaña \textbf{Rendimiento} $\rightarrow$ sección \textbf{CPU} $\rightarrow$ confirmar que indique \textbf{Virtualización: Habilitada}.
    \item \textbf{Memoria RAM:} 8 GB a 16 GB DDR4/DDR5.
    \item \textbf{Almacenamiento del equipo:} Disco de estado sólido (SSD) de 256 GB o 512 GB (SATA o NVMe).
    \item \textbf{Consumo real del software:} Cabe destacar que el sistema operativo Windows 10/11, el entorno .NET 8, PostgreSQL 18 y el sistema ECLESOFT 2.0 consumen en conjunto únicamente entre \textbf{15 GB y 25 GB} de espacio físico. El resto de la capacidad de la unidad (más de 200 GB libres) permanece disponible para el crecimiento del archivo histórico de la base de datos, almacenamiento de copias de seguridad diarias (\textit{backups}) y archivos digitalizados.
    \item \textbf{Conectividad de red:} Tarjeta de red Gigabit Ethernet (LAN cableada) o conexión Wi-Fi estable para la comunicación fluida con las computadoras cliente del despacho.
    \item \textbf{Protección eléctrica recomendada:} Sistema de alimentación ininterrumpida (UPS) de 750 a 1000 VA con supresor de picos para salvaguardar la integridad de la base de datos ante cortes imprevistos de energía eléctrica.
\end{itemize}

\begin{nota}
Las computadoras secundarias (secretarías, despachos o parroquias) \textbf{no requieren instalar ninguno de los programas técnicos listados a continuación}; únicamente necesitan contar con un navegador web actualizado (Chrome, Edge o Firefox) conectado a la misma red del servidor principal.
\end{nota}

\section{Kit de Instalación para Despliegue en Terreno (Memoria USB)}
Para garantizar una instalación fluida y sin contratiempos el día de la puesta en marcha (incluso si la sede parroquial carece temporalmente de conexión a Internet de alta velocidad), se debe preparar una memoria USB con el siguiente contenido:

\begin{enumerate}
    \item \textbf{Copia completa del repositorio:} Carpeta del proyecto conteniendo el código fuente, \texttt{docker-compose.yml}, el script \texttt{BD.sql} y los recursos estáticos.
    \item \textbf{Instalador de Docker Desktop para Windows:} (\texttt{Docker Desktop Installer.exe}) junto con el paquete de actualización del kernel de WSL2 (\texttt{wsl\_update\_x64.msi}).
    \item \textbf{Paquete Plan B (Instalación Nativa sin virtualización):}
    \begin{itemize}
        \item Instalador de \textbf{PostgreSQL 17/18} para Windows (\texttt{postgresql-17.x-windows-x64.exe}).
        \item Instalador de \textbf{.NET 8.0 Hosting Bundle} o \textbf{.NET 8.0 SDK} (\texttt{dotnet-hosting-8.0.x-win.exe}).
        \item Paquete redistribuible \textbf{Microsoft Visual C++ 2015--2022} (x64 y x86).
    \end{itemize}
    \item \textbf{Escudos parroquiales en formato PNG:} Logotipo oficial de la Curia y los escudos específicos de la parroquia para los certificados.
\end{enumerate}

\subsection{Instalación de Docker Desktop (Opción Principal Recomendada)}
\begin{enumerate}
    \item Descargue e instale \textbf{Docker Desktop} desde \url{https://www.docker.com/products/docker-desktop/}.
    \item Asegúrese de marcar la opción \textbf{Use WSL 2 instead of Hyper-V (recommended)}.
    \item Reinicie el equipo si el instalador lo solicita.
    \item Abra Docker Desktop y verifique en la barra inferior que el motor se encuentre en estado verde (\textit{Engine running}).
\end{enumerate}

\subsection{Instalación de .NET SDK 8.0 (Plan B Nativo)}
\begin{enumerate}
    \item Descargue el instalador de \textbf{.NET 8.0 SDK (x64)} para Windows desde \url{https://dotnet.microsoft.com/download/dotnet/8.0}.
    \item Ejecute el instalador y siga los pasos del asistente.
    \item Verifique la instalación abriendo una terminal (PowerShell o Símbolo del sistema) y ejecutando:
    \begin{lstlisting}[style=consola]
dotnet --list-sdks
\end{lstlisting}
    \item La salida debe mostrar una versión perteneciente a la rama \texttt{8.0.x} (por ejemplo, \texttt{8.0.303}).
\end{enumerate}

\subsection{Instalación de PostgreSQL y pgAdmin 4 (Plan B Nativo)}
\begin{enumerate}
    \item Descargue el instalador oficial de PostgreSQL para Windows desde \url{https://www.postgresql.org/download/windows/}.
    \item Ejecute el instalador y, en la ventana de selección de componentes, mantenga marcados \textbf{PostgreSQL Server}, \textbf{pgAdmin 4} y \textbf{Command Line Tools}.
    \item Cuando el asistente solicite definir la contraseña para el superusuario (\texttt{postgres}), ingrese exactamente la clave definida para el sistema:
    \begin{lstlisting}[style=consola]
Clave_curia
\end{lstlisting}
    \item Mantenga el puerto predeterminado \texttt{5432} y continúe hasta finalizar la instalación.
    \item Al terminar, abra \textbf{pgAdmin 4} desde el menú Inicio de Windows y despliegue \textbf{Servers} $\rightarrow$ \textbf{PostgreSQL 18} ingresando la contraseña \texttt{Clave\_curia} para comprobar la conexión.
\end{enumerate}

\begin{consejo}
El instalador de PostgreSQL en Windows registra automáticamente el motor como un \textbf{Servicio de Windows} con inicio automático, por lo que la base de datos se iniciará sola en segundo plano cada vez que se encienda la computadora principal.
\end{consejo}

\subsection{Instalación de Git}
\begin{enumerate}
    \item Descargue Git desde \url{https://git-scm.com/downloads}.
    \item Ejecute el instalador aceptando las opciones predeterminadas.
    \item Verifique la instalación ejecutando en una terminal:
    \begin{lstlisting}[style=consola]
git --version
\end{lstlisting}
\end{enumerate}

\subsection{Instalación de Visual Studio 2022 o Visual Studio Code}
\begin{enumerate}
    \item Descargue Visual Studio 2022 Community desde \url{https://visualstudio.microsoft.com/es/downloads/} o Visual Studio Code desde \url{https://code.visualstudio.com/}.
    \item Si instala Visual Studio 2022, seleccione la carga de trabajo \textbf{Desarrollo de ASP.NET y web}.
    \item Finalice la instalación y verifique que el entorno se inicia correctamente.
\end{enumerate}

\section{Requisitos para el Escenario 2 (Despliegue en la Nube con Google Cloud)}\label{sec:req-cloud}
Para la implementación del sistema en un entorno de alta disponibilidad accesible desde cualquier red sin depender de un equipo físico local encendido, se definen los siguientes requerimientos de infraestructura en la nube:

\begin{table}[h]
    \centering
    \begin{tabular}{|l|l|p{6.5cm}|}
        \hline
        \textbf{Componente} & \textbf{Especificación} & \textbf{Detalles} \\ \hline
        Proveedor Cloud & Google Cloud Platform (GCP) & Proyecto independiente (ej. \texttt{AppCuria}) \\ \hline
        Servicio & Compute Engine & Instancia de Máquina Virtual Linux \\ \hline
        Tipo de Máquina & Serie E2 (\texttt{e2-medium}) & 2 vCPUs y 4 GB de memoria RAM \\ \hline
        Sistema Operativo & Ubuntu 24.04 LTS (o 22.04 LTS) x86/64 & Imagen oficial de servidor Linux \\ \hline
        Disco de Arranque & 30 GB (Disco persistente equilibrado) & Almacenamiento del SO, contenedores y BD \\ \hline
        Cortafuegos (Firewall) & HTTP (80), HTTPS (443) y SSH (22) & Tráfico web público y administración remota \\ \hline
        Motor de Contenedores & Docker Engine + Docker Compose v2 & Orquestación de la aplicación y PostgreSQL 17 \\ \hline
    \end{tabular}
    \caption{Especificaciones de la máquina virtual en Google Cloud (Escenario 2)}
\end{table}

\begin{nota}
La selección de la instancia \textbf{\texttt{e2-medium} (4 GB de memoria RAM)} garantiza una alta capacidad de concurrencia, permitiendo que múltiples iglesias y despachos parroquiales (con 3 a 5 computadoras conectadas simultáneamente por sede) ingresen información de actas, bautismos y catequesis sin degradación en los tiempos de respuesta.
\end{nota}
