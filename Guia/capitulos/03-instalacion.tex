\chapter{Instalación paso a paso}\label{cap:instalacion}

\section{Obtener el código fuente}
\begin{enumerate}
    \item Descomprima el paquete del proyecto en su carpeta de documentos o bien abra una terminal (PowerShell) para clonarlo con Git desde el repositorio oficial:
    \begin{lstlisting}[style=consola]
cd C:\Users\SuUsuario\Documents
git clone https://github.com/whosstixi19/AppCuria.git
\end{lstlisting}
    \item Verifique que dentro de la carpeta del proyecto se encuentre la subcarpeta \texttt{AplicacionCuria} (con el archivo \texttt{AplicacionCuria.csproj}) y en la raíz el script de base de datos \texttt{BD.sql}.
\end{enumerate}

\section{Configurar pgAdmin 4 y crear las tablas}

\subsection{Crear la base de datos \texttt{curia}}
\begin{enumerate}
    \item Abra \textbf{pgAdmin 4} en la máquina principal y expanda en el panel izquierdo \textbf{Servers} $\rightarrow$ \textbf{PostgreSQL 18}.
    \item Haga clic derecho sobre \textbf{Databases} y seleccione \textbf{Create} $\rightarrow$ \textbf{Database...}.
    \item En el campo \textbf{Database}, escriba exactamente en minúsculas:
    \begin{lstlisting}[style=consola]
curia
\end{lstlisting}
    \item Haga clic en el botón \textbf{Save} para crear la base de datos.
\end{enumerate}

\subsection{Ejecutar el script de base de datos (\texttt{BD.sql})}
\begin{enumerate}
    \item En el panel izquierdo de pgAdmin 4, haga clic derecho sobre la base de datos \texttt{curia} recién creada y seleccione \textbf{Query Tool} (Herramienta de consulta).
    \item En la barra superior del editor de consultas, haga clic en el ícono de \textbf{Open File} (Abrir archivo) y seleccione el archivo \texttt{BD.sql} (o copie y pegue su contenido completo en el editor).
    \item Asegúrese de no tener sombreada solo una parte del texto y presione el botón \textbf{Execute script} (ícono de reproducción $\blacktriangleright$ o tecla \textbf{F5}).
    \item En la pestaña inferior \textbf{Messages} deberá mostrarse el mensaje \texttt{Query returned successfully}. Con esto quedarán creadas las 24 tablas del sistema y la cuenta de usuario administrador inicial.
\end{enumerate}

El repositorio contiene archivos históricos de versiones previas (\texttt{Tablas.sql} y \texttt{TablasNuevo.sql}). Para la instalación utilice únicamente el archivo actualizado \texttt{BD.sql}, ya que está 100\% sincronizado con todos los modelos de datos actuales del sistema. Asimismo, verifique en pgAdmin 4 que no quede seleccionado solo un fragmento de texto antes de presionar \textbf{F5}, para que se ejecute el script completo.
\end{alerta}

\section{Configurar la cadena de conexión}
Por motivos de seguridad, al clonar el proyecto desde GitHub el archivo \texttt{appsettings.json} viene con la cadena de conexión en blanco (\texttt{"DefaultConnection": ""}) y el archivo \texttt{appsettings.Development.json} no se incluye en el repositorio público (está listado en \texttt{.gitignore}).

\begin{alerta}
Si intenta ejecutar \texttt{dotnet run} sin antes configurar la cadena de conexión, la consola mostrará el error \texttt{System.InvalidOperationException: The ConnectionString property has not been initialized}. Además, recuerde que si existe el archivo \texttt{appsettings.Development.json}, ASP.NET Core le da prioridad sobre \texttt{appsettings.json}.
\end{alerta}

\begin{enumerate}
    \item Abra el archivo \texttt{appsettings.json} (y, si existe en su carpeta, también \texttt{appsettings.Development.json}) dentro de \texttt{AplicacionCuria}.
    \item En la sección \texttt{ConnectionStrings}, coloque la cadena de conexión apuntando a la base de datos \texttt{curia} con la contraseña asignada a PostgreSQL (\texttt{Clave\_curia}):
\begin{lstlisting}[style=json]
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=curia;Username=postgres;Password=Clave_curia"
  }
}
\end{lstlisting}
    \item Guarde los cambios antes de iniciar el servidor.
\end{enumerate}

\section{Ejecutar la aplicación y habilitar el acceso en red local}

\subsection{Ejecución local en la máquina principal}
\begin{enumerate}
    \item Abra una terminal de PowerShell dentro de la carpeta \texttt{AplicacionCuria} (donde se ubica \texttt{AplicacionCuria.csproj}).
    \item Restaure los paquetes del proyecto y ejecute la aplicación:
    \begin{lstlisting}[style=consola]
dotnet restore
dotnet run
\end{lstlisting}
    \item La consola mostrará que el servidor está escuchando en \url{http://localhost:5155} y que la verificación inicial de recordatorios se ejecutó con \texttt{[OK]}.
\end{enumerate}

\subsection{Habilitar el acceso desde otras computadoras de la red (Cliente--Servidor)}
Para que las demás computadoras de la Curia puedan conectarse mediante su navegador web a la máquina principal:

\begin{enumerate}
    \item \textbf{Política de cookies en red local (\texttt{Program.cs}):} Verifique que en la línea 41 del archivo \texttt{Program.cs} la política de cookies esté definida como:
    \begin{lstlisting}[style=codigo]
options.Cookie.HttpOnly = true;
options.Cookie.SecurePolicy = CookieSecurePolicy.SameAsRequest;
\end{lstlisting}
    Esto permite que los navegadores de las computadoras clientes mantengan la sesión iniciada al conectarse por dirección IP local mediante \texttt{http://}.
    \item \textbf{Abrir el puerto en el Firewall de Windows:} En la máquina principal, abra una ventana de PowerShell como \textbf{Administrador} y ejecute por única vez el siguiente comando para permitir conexiones entrantes al puerto \texttt{5155}:
    \begin{lstlisting}[style=consola]
New-NetFirewallRule -DisplayName "AplicacionCuria 5155" -Direction Inbound -LocalPort 5155 -Protocol TCP -Action Allow
\end{lstlisting}
    \item \textbf{Iniciar el servidor escuchando en toda la red local:} En la carpeta \texttt{AplicacionCuria}, ejecute:
    \begin{lstlisting}[style=consola]
dotnet run --urls "http://0.0.0.0:5155"
\end{lstlisting}
    \item \textbf{Consultar la dirección IP o nombre de equipo de la máquina principal:} En otra ventana de PowerShell de la máquina principal, ejecute:
    \begin{lstlisting}[style=consola]
ipconfig
hostname
\end{lstlisting}
    Anote la dirección \textbf{IPv4} (por ejemplo, \texttt{192.168.1.100} o \texttt{172.29.x.x}) o el nombre del equipo (\texttt{hostname}).
    \item \textbf{Ingresar desde las demás computadoras:} En cualquiera de las computadoras clientes de la red, abra el navegador web e ingrese a \texttt{http://IP\_DE\_LA\_MAQUINA\_PRINCIPAL:5155}.
\end{enumerate}

\begin{nota}
El comodín \texttt{0.0.0.0} se utiliza exclusivamente en el comando \texttt{dotnet run} de la máquina principal para indicarle que acepte conexiones por cualquiera de sus tarjetas de red. En el navegador de las demás computadoras siempre debe escribirse la dirección IPv4 real o el nombre de red de la máquina principal.
\end{nota}

\section{Despliegue en la Nube con Docker en Google Cloud (Escenario 2)}\label{sec:despliegue-cloud}
El Escenario 2 traslada la infraestructura a una Máquina Virtual en Google Cloud Compute Engine, orquestada mediante Docker Compose. Este modelo elimina la necesidad de mantener un servidor físico local encendido de forma permanente en las dependencias de la Curia y otorga acceso global seguro a través de una dirección IP pública.

\subsection{Creación del proyecto e instancia de VM en Google Cloud}
\begin{enumerate}
    \item Inicie sesión en Google Cloud Console (\url{https://console.cloud.google.com}).
    \item En la barra superior, cree o seleccione un proyecto dedicado para la aplicación (por ejemplo, \texttt{AppCuria}).
    \item En el menú lateral o el buscador principal, diríjase a \textbf{Compute Engine} $\rightarrow$ \textbf{Instancias de VM} y presione el botón \textbf{+ Crear instancia}.
    \item Configure los parámetros de la máquina virtual:
    \begin{itemize}
        \item \textbf{Nombre:} \texttt{servidor-curia} (en minúsculas y sin espacios).
        \item \textbf{Región y Zona:} seleccione una región de bajo costo y baja latencia como \texttt{us-central1} (Iowa) o \texttt{us-east1} (Carolina del Sur).
        \item \textbf{Serie y Tipo de máquina:} serie \textbf{E2}, seleccionando el tipo \textbf{\texttt{e2-small}} (2 vCPU, 2 GB RAM) o \textbf{\texttt{e2-medium}} (2 vCPU, 4 GB RAM).
        \item \textbf{Disco de arranque:} haga clic en el botón \textbf{Cambiar}, seleccione \textbf{Ubuntu 24.04 LTS x86/64} (o 22.04 LTS), tipo de disco \textbf{Disco persistente equilibrado} y asigne un tamaño de \textbf{30 GB}.
        \item \textbf{Cortafuegos (Firewall):} en la sección de red, marque las dos casillas obligatorias: \textbf{Permitir tráfico HTTP} y \textbf{Permitir tráfico HTTPS}.
    \end{itemize}
    \item Haga clic en \textbf{Crear} y espere aproximadamente 30 segundos hasta que la instancia muestre el indicador de estado en verde y se le asigne su \textbf{IP externa} pública de Internet.
\end{enumerate}

\subsection{Instalación de Docker y Docker Compose en el servidor}
\begin{enumerate}
    \item En la lista de instancias de Compute Engine, haga clic en el botón \textbf{SSH} ubicado en la fila de \texttt{servidor-curia} para abrir la consola de administración en el navegador web.
    \item Actualice los repositorios del sistema e instale Docker Engine, Docker Compose v2 y Git ejecutando:
    \begin{lstlisting}[style=consola]
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-v2 git
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
\end{lstlisting}
\end{enumerate}

\subsection{Clonación del repositorio y estructura de contenedores}
\begin{enumerate}
    \item Desde la consola SSH del servidor, clone el repositorio oficial del proyecto y acceda a su directorio:
    \begin{lstlisting}[style=consola]
git clone https://github.com/whosstixi19/AppCuria.git
cd AppCuria
\end{lstlisting}
    \item El proyecto incorpora dos archivos diseñados para el despliegue contenerizado:
    \begin{itemize}
        \item \texttt{AplicacionCuria/Dockerfile}: compila la aplicación en .NET 8.0 sobre Ubuntu 22.04 e integra las librerías \texttt{wkhtmltopdf} y fuentes tipográficas necesarias para la generación de actas y certificados en PDF.
        \item \texttt{docker-compose.yml}: orquesta dos servicios interconectados dentro de una red privada virtual de Docker:
        \begin{itemize}
            \item \texttt{curia-postgres}: motor PostgreSQL 18 con volumen persistente (\texttt{postgres\_data}) que inicializa de forma automática las 24 tablas y el usuario administrador montando el script \texttt{BD.sql} en la carpeta interna \texttt{/docker-entrypoint-initdb.d/}.
            \item \texttt{curia-web}: servicio web ASP.NET Core 8 enlazado a la base de datos interna mediante variables de entorno y expuesto al exterior por los puertos HTTP 80 y 5155.
        \end{itemize}
    \end{itemize}
\end{enumerate}

\subsection{Construcción y puesta en marcha con Docker Compose}

    \begin{lstlisting}[style=consola]

    \item Verifique que ambos contenedores se encuentren en estado activo y saludable (\textit{healthy}):

\subsection{Integración y Despliegue Continuo (CI/CD con GitHub Actions)}\label{sec:cicd}
Para automatizar las actualizaciones del sistema sin necesidad de conectarse manualmente por SSH en cada cambio de código, se implementó un flujo de trabajo en GitHub Actions (\texttt{.github/workflows/deploy.yml}):

\begin{enumerate}
    \item \textbf{Integración Continua (CI):} Ante cada confirmación (\textit{push}) en la rama principal (\texttt{main}), un entorno virtual de GitHub compila y valida la solución en .NET 8.0, asegurando la integridad del código fuente antes de cualquier pase a producción.
    \item \textbf{Despliegue Continuo (CD):} Si la compilación es exitosa, GitHub Actions se autentica de forma segura mediante claves SSH en la máquina virtual de Google Cloud y ejecuta de forma autónoma:
    \begin{lstlisting}[style=consola]
cd AppCuria
git pull origin main
sudo docker compose up -d --build
\end{lstlisting}
    \item Este proceso actualiza la aplicación en la nube en menos de 90 segundos con cero tiempo de indisponibilidad para la base de datos.
\end{enumerate}

\subsection{Estrategia de respaldos automatizados en la nube}
En el Escenario 2, la información se almacena de forma persistente e independiente del ciclo de vida de los contenedores mediante el volumen Docker \texttt{postgres\_data}. Adicionalmente, para salvaguardar la información contra fallos mayores o permitir la migración de cuentas:
\begin{enumerate}
    \item Se establece una tarea programada en Linux (\texttt{cron}) que extrae un respaldo diario de la base de datos:
    \begin{lstlisting}[style=consola]
docker exec curia-postgres pg_dump -U postgres curia > /home/backups/curia_$(date +\%Y\%m\%d).sql
\end{lstlisting}
    \item Mediante la herramienta de sincronización \texttt{rclone} o la utilidad de línea de comandos de Google Cloud (\texttt{gcloud storage}), los archivos generados se transfieren automáticamente a un bucket de almacenamiento o a una carpeta designada en \textbf{Google Drive}, garantizando que el personal de la Curia conserve copia de los datos fuera del servidor.
\end{enumerate}
